Zhang（张）的个人作品集网站 —— 一名大学生开发者的数字名片与内容主页。它把博客、项目案例与关于页收进同一条由 MDX 驱动的叙事线上，兼顾个人表达与内容管理。

## 项目定位：数字名片与内容引擎

名片与内容引擎对数据模型、渲染方式和视觉节奏的要求并不一致：名片要在几秒内向访问者交付判断依据，内容引擎要支撑长期、增量、多形态的内容产出。本项目用同一个静态站点同时承担这两种角色，核心课题是——如何在单一路由下把两者统一，而不牺牲其中任何一方的体验。

## 内容系统：MDX 驱动的三层数据流

全站内容收敛在 `content/` 目录的 MDX 文件里。构建前由 `generate-content-data.js` 把每个文件拆成三层，各司其职：

| 产物 | 内容 | 职责 |
|------|------|------|
| `content-data.json` | frontmatter 元信息 | 驱动首页、列表与"精选" |
| `lib/generated/*.mdx` | 剥离 frontmatter 的正文 | 编译为正文组件 |
| `mdx-registry.ts` | slug → Component 映射 | 按路由取用正文组件 |

```ts
import Project0 from '@/lib/generated/projects/zhang.log.mdx';

export const projectComponents: Record<string, ComponentType> = {
  'zhang.log': Project0,
};
```

三层拆分的价值在于**内容与结构的解耦**：元数据与正文各自独立编译，正文组件化让每篇文章可被单独注册与替换——增删一篇内容，只需维护一个 MDX 文件。

## 渲染策略：静态生成的确定性

元信息来自构建期静态数据，正文来自编译期注册组件，路由以 `generateStaticParams` 预生成。整站几乎没有客户端数据请求：首屏确定、构建产物可预期、部署无运行时依赖。这种"用构建确定性换取运行灵活性"的模式，与内容更新频率不高的个人站场景高度契合。

## 国际化：路径段驱动的词典

`app/[lang]` 用路径段承载语言，`getDictionary(lang)` 返回结构化词典，`getDisplayTag` 负责标签本地化。语言被建模为一个路由参数加一次查表动作，没有引入重型 i18n 框架——轻量，且与静态渲染天然兼容。

## 阅读体验：滚动与章节坐标系

`lenis` 提供平滑滚动惯性，`useSectionScrollSpy` 与 `ProjectTableOfContents` 为长文建立章节坐标：右侧目录随阅读进度高亮，小屏收敛为一条波形刻度。配合 `motion` 的区块过渡，方向是让滚动本身成为内容的一部分，为深技术长文提供导航、节奏与坐标感。

## 视觉语言：冷暖、对比与层级

以"lobster"暖橙为强调色，深色底统一全站气质；rounded 卡片与 edge-lit 描边勾勒层级，粗字重标题建立视觉锚点。视觉不抢内容，而是服务于阅读与识别——高级感来自对比、节奏与留白，而非装饰的堆砌。
